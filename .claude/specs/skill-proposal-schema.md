# Skill Proposal Schema

## Overview

The skill proposal schema defines how the RL loop proposes new skills based on detected patterns. This enables self-augmentation: the system learns to extend itself.

## Schema Version: `skill_proposal.v1`

```json
{
  "schema_version": "skill_proposal.v1",
  "proposal_id": "<sha8 hash of proposal content>",
  "timestamp": "<ISO 8601 UTC>",
  "proposed_by": "rl-loop | user | agent-name",
  "name": "skill-name",
  "description": "Clear 1-2 sentence description of what this skill does",
  "trigger_pattern": {
    "action_sequence": [
      {"skill": "planner", "context": "decompose epic"},
      {"skill": "implementer", "context": "write code"},
      {"skill": "test-runner", "context": "validate"}
    ],
    "frequency": 5,
    "episodes": ["ep-abc123", "ep-def456", "ep-ghi789"]
  },
  "specification": {
    "arguments": [
      {"name": "target", "type": "string", "description": "What to operate on"}
    ],
    "acceptance_criteria": [
      "Criterion 1: specific, testable condition",
      "Criterion 2: another condition"
    ],
    "related_skills": ["existing-skill-1", "existing-skill-2"],
    "estimated_complexity": "small | medium | large"
  },
  "validation": {
    "test_cases": [
      {
        "input": {"target": "example"},
        "expected_output": "expected result",
        "acceptance": "Test passes if..."
      }
    ],
    "dependency_check": {
      "circular_dependencies": false,
      "missing_dependencies": []
    }
  },
  "estimated_value": 0.85,
  "confidence": 0.92,
  "status": "proposed | validated | approved | rejected | integrated"
}
```

## Field Definitions

### Core Fields

- **`proposal_id`**: Content-based hash for deduplication
- **`timestamp`**: When the proposal was generated
- **`proposed_by`**: Source of the proposal (RL loop, user, or agent)
- **`name`**: Skill name (kebab-case, matches directory name)
- **`description`**: Human-readable summary

### Trigger Pattern

- **`action_sequence`**: Repeated sequence of (skill, context) pairs
- **`frequency`**: How many times this pattern appeared
- **`episodes`**: Episode IDs where this pattern was observed

### Specification

- **`arguments`**: Input parameters for the skill
- **`acceptance_criteria`**: Testable conditions for validation
- **`related_skills`**: Skills that this composes or extends
- **`estimated_complexity`**: Size estimate (maps to PR scope)

### Validation

- **`test_cases`**: Concrete examples for validation
- **`dependency_check`**: Circular dependency detection results

### Meta

- **`estimated_value`**: Expected improvement in episode reward (0-1 scaled)
- **`confidence`**: RL policy's confidence in this proposal (0-1 scaled)
- **`status`**: Lifecycle state

## Lifecycle States

```
proposed → validated → approved → integrated
           ↓
        rejected
```

- **`proposed`**: Just generated by RL loop
- **`validated`**: Passed `validate-skill` agent tests
- **`approved`**: User confirmed via AskUserQuestion
- **`rejected`**: User or validation rejected
- **`integrated`**: Skill file written, released

## Validation Process

1. **Schema validation**: Ensure JSON conforms to `skill_proposal.v1`
2. **Dependency check**: Run Tarjan's algorithm to detect circular deps
3. **Test execution**: Run validation test cases in sandbox
4. **Complexity estimate**: Verify against repository patterns

## User Approval Gate

When status transitions from `validated` to `approved`, present via AskUserQuestion:

```
AskUserQuestion(
  title="New Skill Proposal",
  questions=[{
    id: "approve-skill",
    prompt: "RL loop proposes new skill: <name>\n\n<description>\n\nDetected in <frequency> episodes. Estimated value: <value>.\n\nView full spec in .claude/rl/proposals/<id>.json",
    options: [
      {id: "approve", label: "Approve — integrate into skill registry"},
      {id: "reject", label: "Reject — discard proposal"},
      {id: "defer", label: "Defer — review later"}
    ]
  }]
)
```

## Integration Workflow

After approval:

1. **Write skill file**: `.claude/skills/<name>/SKILL.md`
2. **Update registry**: Add entry to skill index
3. **Bump version**: Update `.claude/VERSION`
4. **Add changelog**: Update `.claude/CHANGELOG.md`
5. **Trigger release**: Merge to `main` → Issue #3 auto-release workflow

## Storage

Proposals stored at: `.claude/rl/proposals/<proposal-id>.json`

Index maintained at: `.claude/rl/proposals/index.json`

```json
{
  "proposals": [
    {
      "id": "abc123",
      "name": "refactor-large-scale",
      "status": "integrated",
      "timestamp": "2026-03-02T10:30:00Z"
    }
  ]
}
```

## Examples

### Example 1: Refactoring Skill

```json
{
  "schema_version": "skill_proposal.v1",
  "proposal_id": "abc12345",
  "timestamp": "2026-03-02T10:30:00Z",
  "proposed_by": "rl-loop",
  "name": "refactor-large-scale",
  "description": "Refactor codebases with 10+ files, guided by architectural constraints.",
  "trigger_pattern": {
    "action_sequence": [
      {"skill": "planner", "context": "large refactor"},
      {"skill": "refactor-medium", "context": "module A"},
      {"skill": "refactor-medium", "context": "module B"},
      {"skill": "test-runner", "context": "regression"}
    ],
    "frequency": 3,
    "episodes": ["ep-abc", "ep-def", "ep-ghi"]
  },
  "specification": {
    "arguments": [
      {"name": "scope", "type": "string", "description": "Files to refactor (glob pattern)"}
    ],
    "acceptance_criteria": [
      "All tests pass after refactor",
      "Code quality score improves",
      "No breaking changes to public API"
    ],
    "related_skills": ["refactor-medium", "test-runner"],
    "estimated_complexity": "large"
  },
  "validation": {
    "test_cases": [
      {
        "input": {"scope": "src/**/*.rs"},
        "expected_output": "Refactored N files",
        "acceptance": "All Rust tests pass"
      }
    ],
    "dependency_check": {
      "circular_dependencies": false,
      "missing_dependencies": []
    }
  },
  "estimated_value": 0.85,
  "confidence": 0.92,
  "status": "proposed"
}
```
